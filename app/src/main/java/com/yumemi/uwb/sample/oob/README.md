# Ultra-Wideband (UWB) における Out of Band (OOB) の概要

## 📘 OOB（Out of Band）とは？

UWB（Ultra-Wideband）は非常に高精度な測距や位置情報の取得が可能な無線技術ですが、**通信相手を自力で発見（ディスカバリー）する機能を持っていません**。

そのため、UWBで測距セッションを始めるには、**事前に他の通信手段を使ってデバイスを検出し、必要な通信パラメータを交換する必要があります**。

この「UWB以外の通信方式を使って事前に接続準備をする仕組み」を **Out of Band（OOB）メカニズム**と呼びます。

---

## 🔄 OOBの役割

1. **通信相手の検出（Discovery）**
2. **測距パラメータの交換（アドレス、チャネル、セッションキーなど）**
3. **UWB測距セッションのトリガー**

---

## 🔑 交換される主なパラメータ

| パラメータ名     | 説明                               |
|------------|----------------------------------|
| `ローカルアドレス` | セッションごとに割り当てられる一時的な識別子（セキュリティ目的） |
| `UWBチャネル`  | 使用するUWB通信の物理チャネル                 |
| `セッションキー`  | 通信の暗号化に用いる鍵（例：Static STS）        |

---

## 📡 OOBに使用可能な技術

| 技術                             | 特徴                                | 通信距離の目安     |
|--------------------------------|-----------------------------------|-------------|
| **BLE (Bluetooth Low Energy)** | 省電力、Android標準APIで扱いやすい            | 数メートル〜10m程度 |
| **Wi-Fi / Wi-Fi Direct**       | 高速通信が可能。長距離にも対応                   | 10〜50m程度    |
| **Nearby Connections API**     | Google提供。Wi-Fi/Bluetooth/BLEを自動切替 | 3〜30m程度     |
| **Bluetooth Classic**          | 音声や中程度のデータ通信に向く                   | 5〜20m程度     |

---

## 💡 実装例（BLEをOOBとして使用）

1. Android端末がBLEスキャンを実行
2. 相手デバイスがBLEアドバタイズでUWB用の情報をBroadcast
3. `ScanRecord` から以下の情報を取得：
    - UWBアドレス
    - チャネル
    - UUID（サービス識別子）
4. 取得情報を元に `UwbManager` を使ってセッション初期化

---

## 📝 まとめ

| 項目            | 内容                               |
|---------------|----------------------------------|
| **OOBとは？**    | UWB通信を始める前に、他の通信方式を使って相手を見つける仕組み |
| **なぜ必要？**     | UWBにはデバイス検出機能がないため               |
| **どの技術が使える？** | BLE、Wi-Fi、Nearby API など          |
| **いつ使う？**     | 測距セッションの開始前に必ず必要                 |
